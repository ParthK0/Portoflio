## 6. Tier 1 Deep Case Studies

### 01. PROBE — Adaptive Multi-Agent Voice Interview Platform
*Flagship AI & Real-Time Engineering Project*

- **Tags:** `AI` `Real-Time Systems` `Multi-Agent` `Voice RTC` `3D Graphics`
- **Stack:** Next.js 16, React 19, MongoDB, Claude 3.5 / LLM Orchestrator, Agora RTC (STT), ElevenLabs / Cartesia (TTS), MediaPipe, Three.js / React Three Fiber.
- **Role:** Feature Architect · Full-Stack & Systems Contributor (4-person team).
- **Status:** Hackathon Project / Active Build.
- **Card Proof Metric:** Real-time multi-agent handoff · Word-timed 60fps ARKit viseme lip sync.

#### The Problem
Traditional interview-preparation platforms suffer from static, single-agent Q&A scripts. Candidates memorize responses rather than demonstrating true problem-solving depth, and single LLMs lack the adversarial rigor of a real multidisciplinary hiring panel.

#### The Architecture
```text
                    ┌───────────────────────────────┐
                    │   Next.js 16 Client           │
                    │   React 19 / Three.js / Visemes  │
                    └───────────────┬───────────────┘
                                    │ WebSockets / Agora RTC
                                    ▼
                    ┌───────────────────────────────┐
                    │ Interview Session Orchestrator │
                    │ State Machine & Turn Controller│
                    └───────┬───────────────┬───────┘
                            │               │
         ┌──────────────────┼───────────────┴──────────────────┐
         ▼                  ▼                                  ▼
 ┌───────────────┐  ┌───────────────┐                  ┌───────────────┐
 │Technical Agent│  │ Product Agent │                  │  HR / Culture │
 └───────┬───────┘  └───────┬───────┘                  └───────┬───────┘
         └──────────────────┼──────────────────────────────────┘
                            ▼
           Dynamic Competency Graph Evaluator
                            │
                            ▼
              Claude 3.5 Reasoning & Debate
                            │
                            ▼
                 Voice Streaming Pipeline
            Agora STT ──► LLM ──► ElevenLabs TTS
                            │
                            ▼
               Word-Timed Viseme Scheduler
```

#### Three Core Intelligence Layers
1. **Dynamic Competency Graph:** Evaluates technical depth, communication, system design, and product thinking dynamically, updating nodes after every response.
2. **Interviewer Debate Engine:** Technical, Product, and HR agents evaluate responses independently and can challenge or cross-examine candidates when disagreement occurs.
3. **Counterfactual Scenarios:** Shifts parameters mid-interview (e.g., *"What if scale spikes 100x?"* or *"What if Redis is unavailable?"*) to test true problem solving over memorization.

#### What I Worked On
- Multi-agent turn-taking and session state management.
- Backend contract review and candidate/recruiter evaluation flows.
- 3D avatar normalization pipeline and 60fps `VisemeScheduler` for real-time lip synchronization.
- Redis-based transient session caching and skeleton loading states.

#### Engineering Challenges & Key Decisions
- **Challenge: 3D Avatar Scale/Alignment Drift.** Different `.glb` assets produced inconsistent camera framing and broken rigs. Built an automated programmatic normalization pipeline on load rather than hand-tuning raw 3D assets.
- **Challenge: Word-Timed Lip Sync at 60fps.** Audio latency caused mouth movements to desynchronize. Engineered a `VisemeScheduler` that converts transcript timestamps into ARKit blend-shape weights (15 mouth shapes + jaw angle) synced to audio playback buffers.
- **Decision: Agora RTC over HTTP Polling.** Real-time voice interruption and sub-second agent turn-taking required bi-directional streaming audio channels.

### 02. ReconCraft / FinPilot — AI-Verified Financial Reconciliation
*Flagship Fintech & AI Verification System*

- **Tags:** `Fintech` `AI Verification` `Backend Systems` `Deterministic Rules`
- **Stack:** FastAPI, Python Decimal, Pydantic v2, SQLAlchemy 2.0, PostgreSQL (prod) / SQLite (dev), Pandas, Docker, Next.js UI.
- **Role:** Full-Stack Systems Engineer & Architect.
- **Status:** Production-Grade Engineering System.
- **Card Proof Metric:** 100% Precision · 0 False Positives · 0.29s Core Engine Latency.
- **Hook:** *"Why I didn't trust the LLM with the money."*

#### The Pipeline
```text
┌─────────────────┐     ┌───────────────────────┐     ┌────────────────────────┐
│ CSV/Data Upload │ ──► │ Pandas Normalization  │ ──► │ 7 Deterministic Rules  │
└─────────────────┘     └───────────────────────┘     └───────────┬────────────┘
                                                                  │
                                                ┌─────────────────┴─────────────────┐
                                                ▼                                   ▼
                                     [90–95% Resolved Matches]             [Ambiguous Records]
                                     Zero AI Cost / Instant                         │
                                                                                    ▼
                                                                           ┌──────────────────┐
                                                                           │ LLM Verification │
                                                                           │ (Strict JSON)    │
                                                                           └────────┬─────────┘
                                                                                    │
                                                                                    ▼
                                                                           ┌──────────────────┐
                                                                           │ Paisa Arithmetic │
                                                                           │ Validator        │
                                                                           └────────┬─────────┘
                                                                                    │
                                                      ┌─────────────────────────────┴─────────────────────────────┐
                                                      ▼                                                           ▼
                                            [Re-derived Match Valid]                                    [Mathematical Anomaly]
                                            Export to ERP / Ledger                                      Flag for Human Review
```

#### What I Worked On
- The 7-stage deterministic rule matching engine (UTR, Transaction ID, Amount, Timestamp Window, Statutory Rate Card, Tolerance Window, FX Corridor).
- The "Paisa Arithmetic Validator" using Python `Decimal` to verify all numeric LLM outputs before commitment.
- Synthetic ground-truth transaction generator for benchmarking precision and recall.
- FastAPI backend, Pydantic schemas, and Dockerized deployment.

#### Engineering Challenges & Key Decisions
- **Challenge: Verification vs. Hallucination.** LLMs are probabilistic text generators, not arithmetic engines. Solution: Mandated strict Pydantic JSON outputs and forced an independent deterministic re-derivation of all fee, discount, and balance calculations.
- **Decision: Rules-First Architecture.** 90–95% of standard financial records resolve cleanly via deterministic rules. Pushing all records to an LLM introduces unnecessary latency, cost, and risk.
- **Defensible Metrics:**
  - 100% Precision (0 false positives).
  - 100% Recall on verified dataset.
  - 92% benchmark resolution rate.
  - 0.29s engine execution / 0.93s wall-clock for 100 records.
  - 101 tests passed across 25 suites with 79% backend coverage.
  - Reduced manual reconciliation from ~4.6 hours to <1 second per 100-batch.

### 03. Shree Krishna Transport — Production Logistics Platform
*Flagship Production Web Engineering System*

- **Tags:** `Full-Stack` `Production System` `SEO Engineering` `Resilient Dispatch`
- **Stack:** React 19, TypeScript, Vite, Tailwind CSS v4, Framer Motion, Leaflet GIS, Node.js / Express REST API.
- **Role:** Sole Full-Stack Engineer & Architect.
- **Status:** Live in Production (`shree-krishna-transport.org`).
- **Card Proof Metric:** 95+ Lighthouse · 18+ Freight Corridors · 100% Lead Capture Redundancy.

#### The Problem
Regional freight logistics in Western India (Rajasthan, Gujarat, Delhi-NCR) is opaque, dominated by unindexed brokers, phone tag, and high lead abandonment due to friction on traditional inquiry forms.

#### Architecture & Highlights
- **Programmatic Route Engine:** Dynamically powers 18+ corridor landing pages from a typed rate registry, indexing localized transport queries without template duplication.
- **Dual-Channel Lead Redundancy Pipeline:** Form submissions trigger a background EmailJS audit log while instantly redirecting the user to a pre-filled WhatsApp conversation, eliminating lost inquiries.
- **Low-Tier Mobile Optimization:** Lazy-mounted Leaflet map tiles, WebP image formats, and aggressive code-splitting ensure sub-1.5s First Contentful Paint even on throttled 3G/4G connections.

#### Engineering Challenges & Key Decisions
- **Decision: Static Typed Registry vs. Relational Database.** Freight pricing updates weekly or monthly, not per-millisecond. A compiled, strictly-typed TypeScript config registry eliminated database connection pools, reduced hosting costs to $0, and dropped query latency to sub-1ms.
- **Decision: Dual-Channel Dispatch vs. SMTP Gateway.** Small regional fleets need sub-minute response times. Routing straight into WhatsApp gives immediate business conversions while background email captures audit trails.

## 9. Engineering Notes & Architectural Decision Cards

Directly bridges projects into software engineering depth on the homepage:
